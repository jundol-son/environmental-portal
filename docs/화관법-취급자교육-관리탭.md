# 화관법 취급자교육 관리 탭

## 1. 목표

화관법 취급자교육 대상자 명단과 연도별 수료 상태를 등록·조회하고, 현재 수료율과 수료코드를 한 화면에서 관리한다.

## 2. 프로젝트 내 배치

- 기존 `chemicals` Django 앱에 구현한다.
- URL 기준 경로는 `/chemicals/training/`이다.
- 공통 왼쪽 메뉴인 `templates/base.html`의 화관법 하위에 **취급자 교육 관리** 항목을 둔다.
- 기존 Bootstrap 5 UI와 Django 로그인·권한 체계를 재사용한다.
- 교육과정은 **취급자교육** 하나이므로 별도 교육과정 모델을 만들지 않는다.
- 교육 기록은 대상 연도로 구분한다.

## 3. 대상자 식별과 권한

- 대상자 명단의 공식 원본은 관리자가 보유한 엑셀 파일이다.
- `knoxid`를 변하지 않는 사용자 식별자로 사용한다.
- 운영 환경에서는 SSO가 제공하는 `knoxid`로 로그인 사용자와 대상자를 연결한다.
- 외부 개발 환경에서는 SSO 필드가 확정될 때까지 Django `username`을 mock `knoxid`로 사용한다.
- 일반 로그인 사용자는 본인의 수료 현황을 조회하고 수료코드를 제출할 수 있다.
- 교육 담당자는 Django의 `chemicals.change_trainingcompletion` 권한으로 구분한다.
- 교육 담당자는 전체 현황·부서별 수료율 조회, 대상자 엑셀 업데이트, 모든 대상자의 수료코드 등록, CSV 내보내기를 할 수 있다.

## 4. 화면과 기능

### 4.1 교육 현황 대시보드

- 선택 연도의 전체 활성 대상자 수, 수료자 수, 미수료자 수, 수료율을 카드로 표시한다.
- 대상 연도, 부서, 대상자 이름, 수료 상태로 필터링한다.
- 교육 담당자는 이름 일부를 검색해 특정 대상자의 수료 상태와 수료코드를 확인할 수 있다.
- 일반 사용자는 본인 행만 볼 수 있다.
- 일반 사용자는 로그인 계정의 mock `knoxid`와 일치하는 본인 이름과 부서를 확인할 수 있다.
- 교육 담당자는 전체 대상자 목록과 부서별 수료율을 볼 수 있다.
- 목록에는 대상 연도, `knoxid`, 이름, 부서, 수료 상태, 수료코드, 수료 처리 시각을 표시한다.
- 선택 연도의 전체 활성 대상자를 수료율 분모로 사용한다.
- 수료코드를 제출하면 즉시 수료 처리하므로 수료 상태는 수료와 미수료로 구분한다.

### 4.2 대상자 엑셀 대량 업데이트

- 교육 담당자에게만 **엑셀 대량 업데이트** 버튼을 표시한다.
- 업로드 화면에서 대상 연도를 선택한다.
- `.xlsx` 파일의 필수 열은 `knoxid`, `이름`, `부서`이다.
- `knoxid` 기준으로 대상자 정보를 추가하거나 갱신한다.
- 선택 연도에 대상자의 수료 기록이 없으면 새로 만든다.
- 새 업로드 파일에 없는 기존 대상자와 수료 기록은 변경하지 않는다.
- 필수 값 누락이나 파일 내부의 `knoxid` 중복이 있으면 파일 전체를 반영하지 않고 오류 행을 안내한다.

### 4.3 수료코드 제출

- 수료코드는 공백일 수 없다.
- 로그인 사용자는 자신의 `knoxid`와 일치하는 활성 대상 기록에만 제출할 수 있다.
- 목록의 **코드 등록** 버튼을 누르면 수료코드 입력 창을 표시한다.
- 교육 담당자는 모든 대상자의 **코드 등록** 버튼을 사용할 수 있다.
- 제출 즉시 해당 연도의 상태를 수료로 변경하고 처리 시각을 기록한다.
- 이미 수료한 사용자도 코드를 다시 제출할 수 있다.
- 현재 수료 기록에는 최신 코드를 저장하고, 모든 제출 코드는 제출 이력에 원문으로 남긴다.
- 수료코드 원문은 개인정보로 취급하지 않으며 화면과 관리자 CSV에 표시한다.
- 수료코드는 서버 로그와 오류 메시지에는 출력하지 않는다.
- 코드 형식 검증과 교육기관 API 연동은 공식 양식이 확인될 때까지 구현하지 않는다.

### 4.4 CSV 내보내기

- 교육 담당자만 현재 연도·부서·이름·상태 필터 결과를 CSV로 내려받을 수 있다.
- CSV에는 대상 연도, `knoxid`, 이름, 부서, 상태, 수료코드, 수료 처리 시각을 포함한다.
- 한글이 Excel에서 깨지지 않도록 UTF-8 BOM을 사용한다.

## 5. 데이터 모델

### HandlerProfile

- `knoxid`(고유값), 이름, 부서, 교육 대상 활성 여부, 수정 시각

### TrainingCompletion

- 대상자, 대상 연도, 수료 여부, 최신 수료코드, 수료 처리 시각, 수정 시각
- 동일 대상자·동일 대상 연도의 기록은 하나만 유지한다.

### CompletionSubmissionLog

- 대상 수료 기록, 제출자, 제출 수료코드 원문, 제출 시각
- 재제출을 포함한 제출 이력을 보관한다.

## 6. 권한 및 보안

- 모든 교육 URL은 로그인이 필요하다.
- 일반 사용자의 조회와 제출은 서버에서 현재 로그인 사용자의 `knoxid`로 제한한다.
- 엑셀 업데이트와 CSV 내보내기는 `chemicals.change_trainingcompletion` 권한이 필요하다.
- POST 요청은 CSRF 보호와 Django Form 검증을 사용한다.
- 교육 담당자 권한은 Django 관리자에서 그룹 또는 사용자 권한으로 부여한다.

## 7. 향후 확인 사항

- 실제 SSO 프로필의 `knoxid`, 부서, 이름 필드 경로
- 교육기관 수료코드 공식 형식과 추가 검증 규칙
- 만료일 또는 재교육 예정일 계산 기준
- 챗봇 또는 내부 API 연동 방식

## 8. 구현 및 검증 범위

- 모델 변경 시 migration을 생성한다.
- 비로그인 접근, 본인 데이터 제한, 교육 담당자 권한, 엑셀 검증과 갱신, 수료코드 제출·재제출, 수료율 집계, CSV 출력을 Django 테스트로 검증한다.
- 챗봇, 외부 검증 API, 만료일 자동 계산, 알림, 정기 실행 작업은 정책이 확정될 때까지 추가하지 않는다.

- `knoxid` 기반 대상자, 연도별 수료 현황, 수료코드 제출 이력 모델과 migration을 추가했다.
