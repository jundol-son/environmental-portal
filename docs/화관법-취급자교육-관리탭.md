# 화관법 취급자교육

## 1. 목표와 배치

- 기존 `chemicals` Django 앱과 Bootstrap 5 UI를 재사용한다.
- 메뉴는 `화관법 > 교육 > 취급자교육 > 조회/관리`, `종사자교육`으로 구성한다.
- 기존 `/chemicals/training/`은 권한에 따라 개인 조회 또는 관리 화면으로 리다이렉트한다.
- 교육과정 모델은 별도로 만들지 않고 교육 기록을 대상 연도로 구분한다.
- 종사자교육은 이번 범위에서 준비 중 진입점만 제공한다.

## 2. 대상자 식별과 권한

- 대상자 명단의 공식 원본은 관리자가 보유한 엑셀 파일이며 `knoxid`가 불변 식별자다.
- 일반 사용자는 인증 사용자에게서 얻은 `knoxid`와 일치하는 본인 기록만 조회하고 온라인 수료코드를 제출할 수 있다.
- 개발 환경의 기본 `knoxid` 경로는 Django `username`이다.
- 운영 SSO 필드 경로는 `HANDLER_TRAINING_KNOXID_ATTRIBUTE` 설정으로 주입한다. 예: `sso_profile.knoxid`.
- 교육 담당자는 Django의 `chemicals.change_trainingcompletion` 권한으로 구분한다.
- 관리 화면, 대상자 업로드, 수료현황 업로드·양식, CSV 엔드포인트에서 서버 측 권한을 검사한다.

## 3. 수료 판정

최종 수료는 다음 두 조건을 모두 충족해야 한다.

```python
is_completed = bool(online_completion_code.strip()) and offline_completion_date is not None
```

- 온라인 수료: 온라인교육 수료코드가 공백이 아님
- 오프라인 수료: 오프라인교육 수료일자가 있음
- 오프라인 신청일자는 추적 정보이며 최종 수료 조건은 아님
- 수료일자는 신청일자보다 빠를 수 없음
- 수료율은 `최종 수료 인원 / 전체 대상자 수`이며 대상자가 없으면 `0.0%`다.

온라인 처리 시각은 코드가 새로 등록되거나 다른 코드로 변경될 때 갱신한다. 같은 코드의 재제출은 기존 시각을 유지하고, 코드를 삭제하면 처리 시각도 삭제한다. 모든 사용자 제출과 관리자 코드 변경 이력은 `CompletionSubmissionLog`에 원문으로 남긴다.

## 4. 화면과 URL

| 기능 | 경로 | 권한 |
|---|---|---|
| 기존 호환 진입점 | `/chemicals/training/` | 로그인 |
| 개인 조회 | `/chemicals/training/status/` | 로그인 |
| 관리자 화면 | `/chemicals/training/manage/` | 교육 담당자 |
| 코드 제출 | `/chemicals/training/submit/<id>/` | 본인 또는 교육 담당자 |
| 대상자 명단 업로드 | `/chemicals/training/upload/` | 교육 담당자 |
| 수료현황 양식 | `/chemicals/training/manage/excel/template/` | 교육 담당자 |
| 수료현황 업로드 | `/chemicals/training/manage/excel/upload/` | 교육 담당자 |
| CSV 내보내기 | `/chemicals/training/export/` | 교육 담당자 |
| 종사자교육 | `/chemicals/training/worker/` | 로그인 |

개인 조회 화면은 요청 파라미터의 `knoxid`를 사용하지 않는다. SSO 식별자가 없으면 관리자 문의 안내를 표시하며, 해당 연도 기록이 없으면 비대상으로 표시한다.

관리 화면은 대상 연도, 부서, 이름 또는 `knoxid`, 최종 수료 상태로 검색하고 같은 필터를 통계·부서별 수료율·목록·엑셀 양식·CSV에 적용한다. 목록과 CSV에는 온라인 수료코드 원문, 온라인 처리 시각, 오프라인 신청일자와 수료일자를 표시한다.

## 5. 엑셀 처리

### 대상자 명단 업데이트

- `.xlsx` 필수 열: `knoxid`, `이름`, `부서`
- 화면에서 대상 연도를 선택한다.
- `knoxid` 기준으로 대상자 정보를 추가·갱신하고 해당 연도 수료 기록을 만든다.
- 새 파일에 없는 기존 대상자와 수료 기록은 유지한다.
- 필수 값 누락 또는 파일 내 `knoxid` 중복이 있으면 전체 파일을 반영하지 않는다.

### 수료현황 업데이트

- 식별 열: `연도`, `knoxid`
- 참고 열: `이름`, `부서`
- 수정 열: `온라인교육 수료코드`, `오프라인교육 신청일자`, `오프라인교육 수료일자`
- 빈 셀은 기존 값을 유지하고 `__CLEAR__`는 해당 값을 삭제한다.
- 기존 대상자만 수정하며 존재하지 않는 `(연도, knoxid)`는 오류다.
- 잘못된 헤더, 중복 행, 수식 셀, 잘못된 날짜·연도·코드 길이를 검사한다.
- 한 행이라도 오류가 있으면 전체를 롤백한다.
- 기본 제한은 5MB, 5,000행이며 `HANDLER_TRAINING_UPLOAD_MAX_BYTES`, `HANDLER_TRAINING_UPLOAD_MAX_ROWS`로 변경할 수 있다.

CSV는 UTF-8 BOM을 사용하고 `=`, `+`, `-`, `@`로 시작하는 값을 안전하게 이스케이프한다.

## 6. 모델과 마이그레이션

### `HandlerProfile`

- `knoxid`(고유값), 이름, 부서, 활성 여부, 수정 시각

### `TrainingCompletion`

- 대상자, 대상 연도, 최종 수료 여부
- 온라인교육 수료코드, 온라인 처리 시각
- 오프라인교육 신청일자, 오프라인교육 수료일자
- 동일 대상자·동일 연도의 유일 제약

### `CompletionSubmissionLog`

- 대상 수료 기록, 제출자, 제출 수료코드 원문, 제출 시각

마이그레이션 `0003`은 기존 `completion_code`, `completed_at`을 각각 온라인 필드로 rename하여 데이터를 보존한다. 오프라인 수료일자가 없는 기존 레코드는 새 최종 판정식에 따라 미수료로 전환한다.

## 7. 환경 설정과 운영 적용

운영 환경에서 필요한 선택 설정은 다음과 같다.

```python
HANDLER_TRAINING_KNOXID_ATTRIBUTE = "sso_profile.knoxid"
HANDLER_TRAINING_ONLINE_URL = "https://..."
HANDLER_TRAINING_OFFLINE_URL = "https://..."
HANDLER_TRAINING_UPLOAD_MAX_BYTES = 5 * 1024 * 1024
HANDLER_TRAINING_UPLOAD_MAX_ROWS = 5000
```

SSO 필드 경로는 실제 운영 사용자 객체를 확인한 뒤 지정한다. 교육 URL이 없거나 `http`/`https`가 아니면 버튼을 비활성화한다.

운영 반영 순서:

1. DB 백업과 대상 환경을 확인한다.
2. 코드를 배포한다.
3. `python manage.py migrate`로 `chemicals.0003`을 적용한다.
4. 교육 담당자 그룹에 `chemicals.change_trainingcompletion` 권한이 있는지 확인한다.
5. SSO 필드 경로와 교육 URL 설정을 반영한다.
6. 일반 사용자 본인 조회와 관리자 엑셀/CSV 흐름을 실제 계정으로 확인한다.
